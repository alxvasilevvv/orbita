# Рабочие процессы

## Онбординг клиента
Клиент и ресурсы → команда → согласия (кто дал, основание) → подключение OAuth, если доступно → проверка возможностей → бриф и подтверждённые факты в базе знаний → аудит профиля (задачи владельцу с готовыми текстами, т.к. API изменения профиля нет) → стратегия по шаблону → согласование стратегии → план первого месяца.

## Материал
Автор: материал → версия (или AI-черновик) → «Отправить редактору». Редактор: согласовать версию или запросить правки (комментарий обязателен). Клиент: согласовать версию. Менеджер: запланировать в поясе аккаунта. Дальше:
- API-режим: исполнитель публикует, запись «Подтверждено API».
- Режим «через человека»: задача на публикацию; после публикации вставить ссылку, запись «Ручная отметка».
Любая правка после согласования возвращает материал в черновик и отменяет задания.

## Встроенные автоматические сценарии
| Событие | Действие |
|---|---|
| Изменён текст согласованного материала | Аннулировать согласования, отменить задания |
| Публикация подтверждена | Событие `analytics.collect` в outbox |
| Подключение отозвано | Остановить API-задания, задача на переподключение |
| Отозвано согласие на публикацию | Отменить неотправленные задания |
| Ответ LinkedIn потерян | `publication_unknown`, проверка, задача человеку |
| Проверки перед публикацией не пройдены | Снять с расписания, задача менеджеру |

Конструктор пользовательских сценариев (триггер → условия → внутренние действия → согласование) запланирован на этап 3.
