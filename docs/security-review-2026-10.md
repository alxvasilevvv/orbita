# Независимая проверка: найденное и исправленное (2026-10-03)

Проверку выполнял отдельный проход, не видевший процесса разработки. Ниже каждая находка, риск и исправление. Пункты 1–8 и 10, а также причина отмены из пункта 9 покрыты тестами в `test/review-fixes.test.ts`.

| # | Находка | Риск | Исправление |
|---|---|---|---|
| 1 | OAuth страницы компании сохранял URN человека, исполнитель публиковал «страницу» от имени человека | Пост компании выходит в личной ленте сотрудника | При подключении страницы читается `organizationAcls` (роль ADMINISTRATOR, статус APPROVED); организация сохраняется в `managed_accounts.linkedin_urn`. Подключение без роли администратора или другой организации отклоняется. Исполнитель блокирует публикацию (`identity`), если автор страницы не `urn:li:organization:`, а для профиля, если подключён другой человек. Поле идентичности редактируется в «Настройки и доступы» |
| 2 | Новая версия, отзыв согласия, отмена материала и завершение обслуживания отменяли только задания `queued`; задания `awaiting_human` и задачи ручной публикации оставались | Сотрудник публикует устаревший текст или публикует после отзыва согласия | `cancelPendingJobs` отменяет `queued` и `awaiting_human`, закрывает задачи `assisted:` и `publish_blocked:` через `app_close_job_tasks` (SECURITY DEFINER, только для уже отменённых заданий), возвращает запланированные материалы в «согласован» |
| 3 | Представитель клиента мог вызывать внутренние маршруты (задачи, пользователи, очередь взаимодействий, учёт времени), видел абонентскую плату и адреса сотрудников | Утечка внутренней информации агентства клиенту | Список разрешённых маршрутов для клиента и для аудитора, остальное 403. `/api/clients` отдаёт плату только при `view_finance`; `/api/users` только для команды, почта только при `manage_team`; учёт времени только для команды. Комментарии, которые по стратегии согласует клиент, перенесены в кабинет |
| 4 | Роль на аккаунт открывала в RLS весь клиент, включая соседние аккаунты | Владелец профиля видит черновики страницы компании или других сотрудников | RLS v3 (`007_rls_accounts.sql`): отдельные списки клиентов целиком, аккаунтов и «частичных» клиентов; внутренние таблицы закрыты флагом `app.internal` |
| 5 | Повторное планирование той же версии после паузы или ошибки возвращало старое задание как дубликат | Материал не публикуется, хотя интерфейс показывает «запланирован» | Задания `cancelled`, `failed`, `dead` и остановленные `awaiting_human` (режим API) снова ставятся в очередь, задача «публикация остановлена» закрывается. `unknown` не трогается до проверки |
| 6 | Операционный директор мог отключить владельца, можно было отключить себя или последнего владельца | Агентство теряет управление | Владельца отключает только владелец, себя отключить нельзя, последний владелец защищён; чужой пользователь неотличим от несуществующего |
| 7 | Периодические метрики суммировались без проверки периодов; KPI месяца суммировался как число | Повторные снимки удваивают показы и обращения | Сумма только при явных непересекающихся периодах, иначе последний снимок с пояснением; KPI агрегируется по природе из `metric_definitions` |
| 8 | Сохранение процесса клиента выключало общий процесс агентства с тем же ключом | Автоматизация молча перестаёт работать для всех клиентов | Выключаются только версии той же области (`client_id IS NOT DISTINCT FROM`) |
| 9 | Удаление данных клиента не затрагивало выгрузки уровня агентства; причина отмены материала попадала в журнал аудита | Остатки данных удалённого клиента; текст клиента в журнале | Выгрузки агентства удаляются и помечаются истёкшими; причина хранится в `content_items.cancel_reason`, в журнале только `has_reason` |
| 10 | Проверка взаимной поддержки принимала агентство из запроса, использовала `LIKE` и раскрывала в сообщении, что цель принадлежит клиенту агентства | Подбор чужих аккаунтов через сообщение об ошибке | Функция выводит агентство из аккаунта, сравнивает префикс без `LIKE`, фиксирует `search_path`; сообщение не называет клиента |

Дополнительно: ошибка простаивающего соединения пула PostgreSQL больше не роняет процесс (обработчик `pool.on("error")`), аудитор получает отдельный интерфейс только с журналом.
