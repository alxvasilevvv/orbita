# ADR 0001. Модульный монолит + отдельный исполнитель

Статус: принято, 2026-10-02.

Контекст: 500–2 000 аккаунтов, до 50 сотрудников, одна команда разработки. Микросервисы добавили бы распределённые транзакции между согласованием и публикацией без измеримой пользы.

Решение: один TypeScript-кодбейс; HTTP API (Fastify) и worker публикаций как два процесса над одной БД. Модули разделены по папкам `core / services / integrations / ai`, доменная логика `core` не зависит от БД и HTTP.

Почему Fastify, а не Next.js API или NestJS: промпт требует выбрать один серверный подход. Fastify даёт схему-валидацию, быстрый запуск, `inject` для тестов без сети и не привязывает исполнитель к фреймворку UI. UI собран как React SPA (esbuild); перенос в Next.js возможен без изменения API.

Последствия: масштабирование горизонтальное (несколько экземпляров API и worker). Выделение модуля в сервис только при измеримой необходимости.
