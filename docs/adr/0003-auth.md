# ADR 0003. Вход через внешний IdP с MFA

Статус: принято, 2026-10-02.

Решение: приложение не хранит пароли сотрудников. В production перед приложением стоит identity-aware proxy (oauth2-proxy / Pomerium / Cloudflare Access) с IdP (Google Workspace, Entra, Okta) и обязательной MFA; прокси передаёт `x-authenticated-user-id`, приложение принимает его только из доверенной сети (`AUTH_MODE=header`). Режим `dev` с выбором пользователя запрещён при `NODE_ENV=production`.

Вход сотрудника в платформу, OAuth LinkedIn, право на конкретный аккаунт и согласие владельца на вид действий хранятся раздельно (memberships, oauth_connections, consents).
