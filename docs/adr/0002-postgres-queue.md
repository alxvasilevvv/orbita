# ADR 0002. PostgreSQL как БД и очередь публикаций; PGlite для dev и тестов

Статус: принято, 2026-10-02.

Контекст: промпт предлагает Redis-очередь. Объём публикаций сотни-тысячи в сутки; критично, чтобы смена статуса материала и задания были в одной транзакции (transactional outbox).

Решение: задания в таблице `publication_jobs`, атомарный захват `UPDATE … WHERE status = 'queued' RETURNING`, аренда с `lease_until`, истёкшая аренда переводит задание в `unknown`, а не в повтор. События в таблице `outbox` с `dedupe_key`. В dev и тестах используется PGlite (тот же PostgreSQL в WASM), в production `DATABASE_URL`.

Когда пересмотреть: при > 50 000 заданий в сутки или необходимости pub/sub в реальном времени добавить Redis/BullMQ поверх outbox, не меняя контракта.
