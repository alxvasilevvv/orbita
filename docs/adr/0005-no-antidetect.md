# ADR 0005. Без антидетект-браузеров, ротации прокси и мультиаккаунтинга

Статус: принято, 2026-10-16.

## Контекст

Рассматривались инструменты вроде Multilogin: изолированные браузерные профили с подменой отпечатков, резидентные и мобильные прокси с ротацией, облачные телефоны, перенос куки, автоматизация через Selenium, Playwright и Puppeteer. Их назначение: вести много аккаунтов LinkedIn с одной инфраструктуры и скрыть это от платформы.

## Решение

Платформа такие механизмы не использует и не интегрирует.

## Причины

1. LinkedIn запрещает сторонние инструменты автоматизации и маскировку (User Agreement 8.2, Prohibited software and extensions). Это не серая зона.
2. В нашей модели аккаунты принадлежат реальным сотрудникам клиентов. Если инфраструктура связывает много аккаунтов, ограничение получают все сразу, вместе со страницей компании. Ровно этот риск клиент просит исключить.
3. Изоляция, ради которой обычно берут антидетект, у нас решена правильным способом. У каждого сотрудника свой вход и свой аккаунт. Действие выполняет сам владелец или официальный API по его OAuth-токену. Каждое действие одобряется отдельно, лимиты и офицер безопасности работают на стороне платформы.
4. Для криптовалютных и финансовых клиентов маскировка активности создаёт дополнительный регуляторный риск (раскрытие связи с работодателем, правила продвижения).

## Что используем вместо этого

Офицер безопасности: лимиты, разгон, охлаждение по сигналам, правила естественности, проверка текстов. Официальные API LinkedIn после одобрения продуктов. Выполнение действий самим сотрудником с отметкой «Сделал». Egress-прокси только для контроля исходящего трафика сервера (см. `infrastructure-and-proxies.md`), без ротации и маскировки.
