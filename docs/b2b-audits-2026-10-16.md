# B2B-оркестрация: семь независимых аудитов и принятые решения (2026-10-16)

Шесть аудитов проведены по концепции до разработки, седьмой по готовому коду. Каждый аудитор работал отдельно и не видел работы остальных. Ниже главное из каждого отчёта и что сделано в продукте.

## 1. Правила LinkedIn и риск блокировок

| Находка | Решение в продукте |
|---|---|
| Постоянное согласие на реакции противоречит User Agreement 8.2 (действия без участия человека) | Постоянных согласий нет. Каждое действие одобряет владелец аккаунта в момент выполнения, одобрение фиксируется (`decided_by`, `decided_at`, хеш текста) |
| Для комментариев и реакций от имени участника нужен Community Management API (`w_member_social_feed`), self-serve `w_member_social` этого не даёт | Операция `write_comments` разделена на `comment_member` и `comment_org`. Матрица возможностей исправлена |
| Developer AI Policy: AI не создаёт комментарии к контенту, автор которого не пользователь приложения | AI-черновик готовится только к постам страницы компании, которые есть в платформе. К чужим постам сотрудник пишет сам |
| Лимиты рассчитаны на SMM-аккаунт, а не на сотрудника | Лимиты сотрудника: 2 комментария, 5 реакций в сутки, 1 комментарий в час, 6 в неделю. Разгон 14 дней с половиной лимитов |
| Правила естественности слабые | На пост не больше 25% подключённых и не больше 5 человек. Первый час после публикации без действий. Между действиями не меньше 45 минут. Окно 2–72 часа. Похожесть текстов проверяется по всему агентству за 90 дней |
| Нет реакции на сигналы LinkedIn | 429 даёт охлаждение 24 часа. Два 403 подряд выключают API-режим. Скрытые комментарии дают охлаждение 7 дней. Предупреждение, капча, ограничение и проверка личности дают охлаждение 24 часа |
| Браузерная механика плейбука (Chrome MCP) попадает под Prohibited software | Не переносится. Из плейбука взяты устав, лимиты, разгон, аварийная остановка, единый источник истины, CATCHUP без залпа |

## 2. Безопасность и доступы

| Находка | Решение |
|---|---|
| Любая новая роль считалась внутренней | `EXTERNAL_ROLES = client, client_admin, auditor` во всех проверках. CHECK в БД: `client_admin` только на клиента |
| Руководитель мог одобрять и давать согласия за сотрудника | `assertAccountOwner` для одобрения, отметки «Сделал» и согласия на аккаунт сотрудника. У `client_admin` нет `manage_consent` |
| RLS открывал руководителю всё по сотрудникам | RLS v4: таблицы «по владельцу» (`mission_actions`, `safety_events`, `account_safety`, `employee_profiles`, `consents`). Вне агентства их видит только владелец аккаунта. `agent_runs` и `employee_invites` доступны только агентству |
| Токены приглашений | 32 байта, в базе только хеш, 72 часа, одноразовые. Атомарное принятие, лимит частоты |
| Prompt injection через бриф и текст поста | Бриф и пост передаются как данные в разметке. Проверка на инструкции. Агент без инструментов, вывод проверяется схемой. Бриф руководителя утверждает агентство |
| Аварийная остановка | Ставят руководитель и агентство. Причина обязательна. Снимает только агентство |

## 3. Архитектура агентов

| Находка | Решение |
|---|---|
| Гонка лимитов | Проверка и запись в одной транзакции под `pg_advisory_xact_lock` по аккаунту. При планировании действие резервирует квоту, при одобрении и исполнении считаются только подтверждённые |
| Двойное планирование при нескольких воркерах | `agent_runs` с уникальным `(agent, trigger_key)`. Повторный или параллельный запуск пропускается |
| LLM там, где нужен код | Стратег, планировщик, офицер безопасности, оценка риска и похожесть текстов написаны детерминированным кодом. LLM только пишет черновики |
| Простой | Просроченные предложения истекают. Миссии закрываются. После восстановления нет залпа действий |
| Деградация без AI | Планирование и безопасность работают без AI. Без черновика сотрудник пишет текст сам |

## 4. Право и регуляторика (не юридическое заключение)

| Находка | Решение |
|---|---|
| Профили «с международным бэкграундом» читаются как запрос на подставные профили | Подключаются только реальные сотрудники по личному приглашению. Трудоустройство подтверждается по домену почты или HR. Агенты не редактируют историю работы |
| Продвижение криптоактивов (MiCA ст. 66, FCA с 8.10.2023, VARA Marketing Regulations) | Флаг отрасли в брифе. Для `crypto` и `fin` блокируются обещания доходности, FOMO, прошлая доходность без оговорки и призывы к депозиту. Новости и собственные посты требуют утверждения compliance клиента |
| Скрытая связь с работодателем (FTC 16 CFR 255 и 465, UK DMCC, UCPD) | Режим раскрытия. Для регулируемых отраслей он принудительно `inline`, текст без раскрытия блокируется |
| GDPR: согласие работника несвободно, мониторинг работников | Участие добровольное. Пропуск без последствий. Руководитель видит только агрегаты от 5 человек. Нужны DPIA и LIA (шаблоны в планах) |
| Трудовой риск | Участие не учитывается в KPI. Руководитель не видит отказы, риск и черновики конкретного человека |

## 5. Продукт и UX

| Находка | Решение |
|---|---|
| Метрики из плейбука продаж не подходят цели «доверие» | Первый экран руководителя «Как нас видят»: подписчики страницы и динамика, посты за 30 дней, дни с последнего поста, вакансии |
| Миссии почти только про усиление | Типы миссий: технический разбор, инженерный блог, open source, выступление, вакансия, новость компании, поддержка поста, обсуждение |
| Риск принуждения | Не больше 1 запроса в неделю, пауза в один клик, «Пропуск ни на что не влияет». Перед принятием приглашения видно, что увидит руководитель |
| Онбординг | Приглашение, темы экспертизы, частота, самооценка активности, согласия на одной странице |

## 6. Данные и честность аналитики

| Находка | Решение |
|---|---|
| Правило «50% своей компании» нельзя посчитать на доступных данных | Заменено самооценкой активности сотрудника. Если данных нет, уровень риска не ниже среднего |
| Формула риска давала 120 баллов | Риск v2: сначала запреты (охлаждение, исключение, ошибка подключения, 3 сигнала за 30 дней), затем веса 35/25/15/15/10 с затуханием сигналов |
| Граница суток пробивала лимит | Скользящие окна 60 минут, 24 часа и 7 дней, которые содержат момент действия |
| Похожесть по словам слабая на русском | Символьные шинглы длины 5: блок от 0,35, предупреждение от 0,25. Минимум 8 слов. Фильтр шаблонов |
| Свои действия выдавались бы за результат | Работа команды («сделано») показывается отдельно от результата. Результат «не рассчитывается», пока нет показов |

## 7. Итоговый аудит кода (после разработки)

| Находка | Исправление |
|---|---|
| Токен приглашения возвращался руководителю | Ссылка уходит сотруднику письмом. В production принять приглашение может только вошедший через IdP пользователь, которому оно выдано. Ссылка видна только в демо-режиме |
| Причины отсева и журнал агентов раскрывали руководителю риск конкретных людей | Руководитель получает только число запланированных действий и участников. Журнал агентов и причины отсева видит только агентство |
| Руководитель открывал черновики личных аккаунтов сотрудников | `accountScope` закрывает руководителю личные аккаунты: доступна только страница компании |
| Агрегаты без порога | Счётчики миссии показываются от 5 участников. Распределение риска скрывает ячейки меньше 5. Сигналы руководителю показываются статусом, без чисел. Уведомления директора руководителю без цифр |
| Гонка в одобрении и отметке «Сделал» | Повторная проверка под блокировкой, `FOR UPDATE`, обновление только из ожидаемого статуса |
| Согласие сотрудника мог дать менеджер агентства | Для аккаунтов сотрудников согласие даёт только владелец |
| Признак «пост компании» брался из запроса | Признак ставится только при совпадении ссылки с опубликованным постом страницы в платформе. Запрет AI распространён на все действия с внешними целями |
| Восстановление не работало: старые сигналы снова исключали аккаунт | Сигналы считаются только после последнего восстановления агентством |
| Миссия зависала в «планируется» при ошибке | Миссия останавливается с понятной причиной. Ошибка пишется в журнал агентов |
| Частота проверялась вне блокировки | Проверка частоты перенесена в офицера безопасности под блокировку |
| Зависшее «выполняется» | Через 15 минут статус «исход неизвестен»: без повтора, проверяет человек |
| Перебор адресов при приглашении | Ответ нейтральный. Лимит частоты на предпросмотр и принятие |

Известное ограничение. Таблицы контента (`content_items`, `content_versions`, `ai_executions`, `action_records`) на уровне БД не разделены «по владельцу»: руководителю закрыт доступ на уровне сервисов (`accountScope`). Перевод этих таблиц в режим «по владельцу» с учётом типа аккаунта запланирован отдельной миграцией.

## Отклонённое: антидетект и мультиаккаунтинг

Мы изучили Multilogin и аналогичные решения: поддельные отпечатки браузера, резидентные и мобильные прокси с ротацией, облачные телефоны, готовые куки, автоматизация через Selenium и Playwright. Решение: такие решения в платформу не встраиваем, см. `docs/adr/0005-no-antidetect.md`.
